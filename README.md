# anavi-resource

Демо платформы Anavi целиком: фотографии, выгруженные таблицы, книга, слова обращений — **и сам сид**, который проводит всё это через слой сервисов бэкенда.

## Зачем отдельно

Почти гигабайт против нескольких мегабайт кода. Git хранит каждую версию двоичного файла вечно, поэтому перерисовка баннера оставалась бы в весе каждого клона.

Сначала сюда уехали фотографии, потом данные, потом сид: строка товара, снимок на ней и функция, которая её заводит, — одна фикстура. Пока они лежали в двух репозиториях, сид в репозитории кода был больше платформы: 105 тысяч строк против 78 тысяч.

## Как подключается

Сид зовёт сервисы бэкенда, а бэкенд приходит сюда симлинком:

```bash
cd anavi/code/backend && bun link
cd ../shared             && bun link
cd ../../../anavi-resource && bun install
```

После этого `seed/` импортирует `@anavi/backend/src/modules/…` как раньше импортировал `@/modules/…`, и `tsc` проверяет всё это здесь, своим `tsconfig.json`.

```
sss/
├── anavi/           код
└── anavi-resource/  этот репозиторий: материал и сид
```

**Ни `drizzle-orm`, ни `sharp` здесь быть не должно**: оба пришли бы вторыми копиями — две сущности каждой колонки, из-за которых `tsc` откажется собирать, и вторая нативная libvips в одном процессе. Операторы drizzle приходят из `@anavi/backend/src/db`, кодирование PNG — из `@anavi/backend/src/lib/images`.

Материал сид находит сам (`import.meta.dir`). Без картинки демо соберётся, без файла данных упадёт: каталог, приехавший наполовину, — не демо.

## Как запускать

Из репозитория кода, там лежит `.env` с адресом базы:

```bash
bun run --cwd code/backend db:reset      # снести схему, накатить миграции, собрать все демо
bun run --cwd code/backend seed          # только собрать демо
bun run --cwd code/backend seed:sales    # набить продажи (руками, никогда частью db:reset)
```

Проверки живут здесь: `bun run typecheck` и `bun run lint:fix`. **Бэкенд их не видит** — переименование сервиса ломает сид молча.

## Устройство

Всё, что принадлежит демо, лежит в `demos/<имя>/`: материал рядом с кодом, который его заводит. Имя папки — адрес сайта `<имя>.anavi.localhost` (то, что в `org_site.slug`). Номеров нет: новое демо — папка `demos/<имя>/` и строка в `seed/demos.ts`.

```
demos/<имя>/            одно демо целиком
├── seed/               код, который его заводит
├── sales.json          его продажи: свои люди, свои обращения, свои разговоры
├── brief.json          слова демо агенту: чем торгует, каких карточек и снимков хочет
├── logo.png            логотип организации
├── hero/               первый экран
├── categories/         обложки разделов и подборок, по слагу
├── brands/             знаки производителей, по слагу значения
├── collections/        плитки подборок
├── products/           фотографии товаров, `<слаг>-<номер>`
├── data/               выгруженные таблицы каталога, если демо собрано из них
├── prompts.html        чем это снято: голая разметка, стили общие
└── ...                 остальное по смыслу демо
shared/                 материал, который не принадлежит одному демо
├── sales.json          общие слова продаж: банки и слова журнала заказа
├── supplies.json       условия поставок между организациями
├── provider-*.json     письма и работы исполнителей услуг
├── shelf-*.json        отзывы и слова полки
└── prompts.css, .js    общий лист и поведение промптовых страниц
seed/
├── main.ts, index.ts   вход и оркестратор сброса
├── demos.ts            список демо: единственное место, где перечислены адреса
├── lib/                то, чем пользуется каждое демо: ресурсы, картинки, блоки, анкеты, места
├── links/              то, что связывает демо между собой: поставки, хранение и перевозка, рассрочка
├── sales/              прогон продаж, `seed:sales`
└── shelf/              прогон полок, `seed:shelf`
```

Имя файла значимо: обложка раздела — его слаг, знак бренда — слаг значения свойства, фотографии товара — `<слаг>-<номер>`.

**Данные лежат рядом со своими картинками.** Каталог «Веги» — это `demos/vega/data/*.json` и `demos/vega/phones/*.webp`: одна фикстура, снятая с двух сторон. Сид читает их одной дверью — `resourceJson` для таблицы, `seedImage` для снимка.

**Продажи в два слоя.** `shared/sales.json` — общие слова (банки, слова журнала заказа). `demos/<имя>/sales.json` — продажи самого демо и необязателен: без него прогон проходит без продаж, а каталог и книги стоят. Чужими продажами демо не набивают.

**Промптовая страница — голая разметка.** Стили и поведение лежат в `shared/`, страница приносит только своё: акцент на `<html style="--accent: …">` и имя хранилища отметок на `<body data-key="…">`.

## Материал «Тулпара»

Первое демо без каталога: материал — слова и сетка, не таблицы товаров. Пять файлов рядом с кадрами:

- `site.json` — организация, пять точек, девять страниц по разделам, четыре анкеты и меню. Раздел страницы называет кадр по имени файла без расширения (`fulfilment/receiving`).
- `content.json` — база знаний по четырём группам, пять новостей с телом по абзацам, пять работ.
- `tariffs.json` — семь направлений, ставки склада, правила доставки, склад карго с адресом, запрещённое и надбавки.
- `sales.json` — обращения и переписки, как у всех.
- `hauls.json` — автопарк и то, что ездит между городами: перемещения клиентов между точками, рейсы с остановками и погрузкой, слова диспетчера. Веса в килограммах, размеры в миллиметрах, деньги в целых сомах; точки названы номером по порядку у своего сайта.

**Числа записаны так, как их читает человек:** деньги в целых единицах, вес ступеней в килограммах, страховка в процентах. Сид переводит их в минорные единицы, граммы и сотые доли процента. Направление у склада карго и в ответах калькулятора (`route`) — ключ из `tariffs.json`, а не номер: номера рождаются при прогоне.

**Тексты и сетка сверены друг с другом.** Каждая сумма в переписке или новости (девятьсот сомов до Оша, 167,40 доллара за 62 килограмма) получена счётной функцией платформы на этой сетке. Правите ставку — перечитайте `sales.json` и `content.json`.

Материал придуман: ни адреса, ни ставки, ни расписание рейсов не взяты у живого перевозчика.

## Материал «Авто996»

Самое маленькое демо, и нарочно: сорок машин, три площадки в жилмассивах, каталог с фильтром, контакты и заявка во входящие. Корзины, оплат, партнёров и перевозчика нет, с другими демо оно не связано — его можно убрать, не читая чужих сценариев.

`cars.json` — машины со своими фактами: марка, год, пробег, цена в долларах, характеристики кодами словаря. Фотографии в `cars/`, `<слаг>-<номер>.webp`. Всё перенесено из архивного проекта площадки автопарков, где объявления собирались с mashina.kg. Отбор — машины с пробегом в наличии, не меньше трёх кадров уже в 4:3 и первый такой же, дешевле 60 000 долларов, с правдоподобным пробегом. Кадры не обрабатывались и не генерировались.

## Исходный материал «Ватта»

`demos/watt/source/` — сырьё каталога и генератор, который делает из него `demos/watt/data/`; конвейер целиком в одном репозитории. Подробности — в `demos/watt/source/SOURCE.md`. Сид читает `data/`, но не `source/`: восемнадцать мегабайт payload'ов ему не нужны.

## Людей не показываем

**Лица нет ни на одной фотографии.** Сгенерированное лицо читается как подделка мгновенно, а подпись под ним — имя, должность, стаж — превращает картинку в фабрикацию чужой квалификации. Ни одно демо не заводит портретов и не называет людей по именам.

Фигура не запрещена: человек может быть в кадре, но не быть его предметом — со спины, в отдалении, руки за работой. Портрет команды, врач у кресла, консультант за столом не снимаются. Для одежды это решает то же, что вся товарная съёмка: манекен-невидимка, раскладка на плоскости, макро на строчку — не обход ограничения, а отраслевой стандарт каталога.

## Правила

Форматы — `png`, `jpeg`, `webp`, `avif`, `gif`; до 8 МБ и 4096 пикселей по стороне. Сид сам жмёт всё в webp и делает миниатюру: чем ближе к оригиналу, тем лучше результат.

**Прозрачность несут только `png` и `webp`, и для вырезанной карточки это решает выбор формата.** На фотографии ткани png раздувается впятеро против webp при том же качестве, поэтому вырезы лежат в webp с альфой — так карточки швейного цеха. `compressImage` пережимает в webp и фон не заливает. Сцены — цех, работы, ткани, обложки полок — остаются `jpg`.

Кэш обработки — `.seed-cache/assets.json`, ключ — хеш содержимого: одна картинка в двух демо — один объект в хранилище. Замена файла подхватывается сама; после смены качества сжатия кэш сбрасывается через `SEED_FRESH_ASSETS=1`.

**Кто отвечает, тот и ведёт.** Сид раздаёт обращения по столу по кругу и назначает исполнителем того же человека, который в нём пишет: «отвечает один, назначено на другого» — состояние, которого в жизни не бывает, и в фикстуре его быть не должно.

## Чего демо не показывает

Дыры материала и сида — что сцена не разыгрывает, где материал придуман, что оставляет прогон продаж — собраны в `DEMO.md`. Ограничения самой платформы живут в `DEFERRED.md` её репозитория.
