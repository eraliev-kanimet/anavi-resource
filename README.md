# anavi-resource

Демо платформы Anavi целиком: фотографии, выгруженные таблицы каталогов, книга, слова каждого обращения — **и сам сид**, который проводит всё это через слой сервисов бэкенда.

## Зачем отдельно

Это самая тяжёлая часть проекта: почти гигабайт против нескольких мегабайт кода. Git хранит каждую версию двоичного файла — и стотысячестрочного JSON — вечно, поэтому внутри дерева исходников любая перерисовка баннера и любая пересборка каталога навсегда оставались бы в весе каждого клона.

Сначала сюда уехали только фотографии, потом данные, потом сам сид. Причина одна и та же: строка товара, снимок на ней и функция, которая её заводит, — одна фикстура. Пока они лежали в двух репозиториях, сид в репозитории кода был больше платформы, которую наполняет: 105 тысяч строк против 78 тысяч.

## Как подключается

Сид зовёт сервисы бэкенда, а бэкенд приходит сюда симлинком — обычной ссылкой npm:

```bash
cd anavi/code/backend && bun link
cd ../shared             && bun link
cd ../../../anavi-resource && bun install
```

После этого `seed/` импортирует `@anavi/backend/src/modules/…` ровно так, как раньше импортировал `@/modules/…`, и `tsc` проверяет всё это здесь, своим `tsconfig.json`.

```
sss/
├── anavi/           код
└── anavi-resource/  этот репозиторий: материал и сид
```

**Ни `drizzle-orm`, ни `sharp` в зависимостях здесь нет и быть не должно.** Оба пришли бы вторыми копиями: две сущности каждой колонки, из-за которых `tsc` откажется собирать, и вторая нативная копия libvips в одном процессе. Операторы drizzle приходят из `@anavi/backend/src/db`, кодирование PNG — из `@anavi/backend/src/lib/images`.

Материал сид находит от себя (`import.meta.dir`), никакой переменной для этого не нужно. Отсутствие одной **картинки** демо не ломает — соберётся без неё; отсутствие файла **данных** роняет: каталог, приехавший наполовину, — это не демо.

## Как запускать

Из репозитория кода, потому что там лежит `.env` с адресом базы:

```bash
bun run --cwd code/backend db:reset      # снести схему, накатить миграции, собрать десять демо
bun run --cwd code/backend seed          # только собрать демо
bun run --cwd code/backend seed:sales    # набить продажи (руками, никогда не частью db:reset)
```

Проверки живут здесь: `bun run typecheck` и `bun run lint:fix`. **Бэкенд их не видит** — переименование сервиса ломает сид молча, пока эти две команды не запущены.

## Устройство

Папка на демо, внутри — по назначению. Имя файла значимо: обложка раздела зовётся его слагом, знак бренда — слагом значения свойства, фотографии товара — `<слаг>-<номер>`.

```
seed/                 сам сид: оркестратор, папка на демо, общий скрипт продаж
prompts.css           общий лист промптовых страниц
prompts.js            их же поведение: отметки о закрытых кадрах
sales.json            материал общего скрипта продаж: люди, реплики, слова журнала заказа
<демо>/
├── sales.json        продажи этого демо: свои люди, свои обращения, свои разговоры
├── logo.png          логотип организации
├── hero/             первый экран
├── categories/       обложки разделов и подборок, по слагу
├── brands/           знаки производителей, по слагу значения
├── collections/      плитки подборок
├── prompts.html      чем это снято: голая разметка, стили общие
├── data/             выгруженные таблицы каталога, если демо собрано из них
├── books/            изданная книга, если демо её публикует
└── ...               остальное по смыслу демо
```

**Данные лежат рядом со своими картинками, а не отдельной веткой дерева.** Каталог «Веги» — это `vega/data/*.json` и `vega/phones/*.webp`: одна фикстура, снятая с двух сторон. Сид читает их одной дверью — `resourceJson` для таблицы, `seedImage` для снимка.

**Продажи устроены в два слоя.** Корневой `sales.json` — материал, которым набивается любое демо, ещё не написавшее своего: состав действующих лиц, реплики гостя и менеджера, слова, которыми пишется журнал заказа. `<демо>/sales.json` перекрывает его целиком: обращения этого демо своими словами, с его людьми и его случаями. Первый обязателен, второй нет — его отсутствие означает «у этого демо ещё не дошли руки», а не поломку.

**Промптовая страница демо — голая разметка.** Стили и поведение лежат общими файлами в корне, а страница приносит только своё: акцент на `<html style="--accent: …">` и имя хранилища отметок на `<body data-key="…">`. До этого каждая таскала свою копию — шесть с половиной килобайт одинакового CSS в трёх файлах, различавшихся ровно одной строкой.

| папка    | демо                        | данные            |
| -------- | --------------------------- | ----------------- |
| `hanako` | Ханако — моторные масла     | —                 |
| `vega`   | Вега — ноутбуки и смартфоны | `data/` 37 таблиц |
| `dyikan` | Дыйкан — продуктовый рынок  | —                 |
| `watt`   | Ватт — бытовая техника      | `data/` + `source/`, `reviews.json`, `accessories.json` |
| `saima`  | Сайма — швейный цех         | —                 |
| `tulpar` | Тулпар — логистический оператор | `site.json`, `content.json`, `tariffs.json`, `hauls.json` |

## Материал «Тулпара»

Первое демо без каталога, поэтому его материал — не таблицы товаров, а слова и сетка. Четыре файла рядом с кадрами:

- `site.json` — организация, пять точек, девять страниц по разделам, четыре анкеты и меню. Раздел страницы называет кадр по имени файла без расширения (`fulfilment/receiving`).
- `content.json` — база знаний по четырём группам, пять новостей с телом по абзацам, пять работ.
- `tariffs.json` — семь направлений, ставки склада, правила доставки, склад карго с адресом, список запрещённого и надбавок.
- `sales.json` — обращения и переписки, как у всех.
- `hauls.json` — автопарк и то, что ездит между городами: перемещения клиентов между их точками и рейсы с остановками, погрузкой и словами диспетчера с дороги. Веса в килограммах, размеры в миллиметрах, деньги в целых сомах; точки названы номером по порядку у своего сайта.

**Числа сетки записаны так, как их читает человек, а не платформа:** деньги в целых единицах валюты (сомы, доллары — с копейками через точку), вес ступеней в килограммах, страховка в процентах. Сид переводит их в минорные единицы, граммы и сотые доли процента. Направление у склада карго и в ответах калькулятора (`route`) названо ключом из `tariffs.json`, а не номером: номера рождаются при прогоне.

**Тексты и сетка проверены друг против друга.** Каждая сумма, названная в переписке или в новости (девятьсот сомов до Оша, 167,40 доллара за 62 килограмма), получена счётной функцией платформы на этой сетке. Правите ставку — перечитайте `sales.json` и `content.json`: они цитируют её числами.

**Материал придуман.** Ни адреса, ни ставки, ни расписание рейсов не взяты у живого перевозчика.

## Архив

`archive/` — то, что было построено и снято с проекта, но выбрасывать жалко. Не документация и не черновик: каждый файл открывается в браузере и работает. Сегодня там один — `glass-header.html`, второй вариант шапки витрины, живший под настройкой сайта `headerStyle: 'glass'`: навигация плавающими островами матового стекла и скрипт, замерявший яркость фотографии под ними. В коде его больше нет нигде.

## Ролик первого экрана

Скролл-герой не проигрывает видео, а перематывает его кадром — и решает это **файл, а не браузер**: опорный кадр раз в две секунды даёт рывки везде, каждый кадр опорный — гладко везде. Поэтому ролик готовится один раз руками и лежит в материале демо уже готовым:

```bash
bun seed/reel.ts <исходник> <демо>/hero/reel.mp4
```

Команда пересобирает в 1200 пикселей шириной, каждым кадром опорным и без звуковой дорожки, режет рядом заставку из первого кадра (`reel-poster.jpg` — она же стоит под видео, пока оно грузится) и печатает разбор результата. Исходники сюда не кладём: git хранит каждую версию двоичного файла вечно, а готовый ролик обычно меньше того, из чего сделан.

`seedReel` читает заголовок mp4 сам, без `ffmpeg`, и **роняет сид**, если ролик не весь из опорных кадров, несёт звук, длиннее двадцати секунд или шире полутора тысяч. Дёргающаяся промотка — это не «чуть хуже», это отсутствие приёма, ради которого блок существует.

## Исходный материал седьмого демо

У «Ватта» рядом с картинками лежит `watt/source/` — сырьё, которым собран его каталог, и генератор, который превращает одно в другое. Раньше генератор писал результат в репозиторий кода через переменную `ANAVI_DIR`; теперь он пишет в соседнюю `watt/data/`, и конвейер целиком помещается в один репозиторий. Подробности — в `watt/source/SOURCE.md`.

Сид читает `watt/data/`, но не `watt/source/`: восемнадцать мегабайт payload'ов ему не нужны.

## Людей не показываем

**Лица не бывает ни на одной фотографии.** Сгенерированное лицо читается как подделка мгновенно, а подпись под ним — имя, должность, стаж — превращает картинку в фабрикацию чужой квалификации. Ни одно демо не заводит портретов и не называет людей по именам.

Фигура при этом не запрещена: клининг снят так, что сотрудник виден со спины или в отдалении, руки за работой — тоже нормальный кадр. Правило простое: **человек может быть в кадре, но не может быть его предметом**. Всё, где посетителю предлагают смотреть на конкретного человека, — портрет команды, врач у кресла, консультант за столом — не снимается.

Для одежды это решается тем же, чем решает вся товарная съёмка: **манекен-невидимка** (вещь держит форму, внутри никого), раскладка на плоскости и макро на строчку. Это не обход ограничения, а отраслевой стандарт каталога.

## Правила

Форматы — `png`, `jpeg`, `webp`, `avif`, `gif`; до 8 МБ и 4096 пикселей по стороне. Сид сам жмёт всё в webp и делает миниатюру, поэтому класть сюда пожатое заранее не нужно — наоборот, чем ближе к оригиналу, тем лучше результат.

**Прозрачность несут только `png` и `webp`, и для вырезанной карточки это решает выбор формата.** На фотографии ткани png раздувается впятеро против webp при том же качестве, поэтому вырезы лежат в webp с альфой — так карточки швейного цеха. Сид прозрачность не теряет: `compressImage` пережимает в webp и фон ничем не заливает. Сцены — цех, работы, ткани, обложки полок — остаются `jpg`: у них нет фона, отделимого от предмета.

Кэш обработки лежит в `.seed-cache/assets.json` и ключуется хешем содержимого: одна и та же картинка в двух демо — один объект в хранилище. Замена файла подхватывается сама; если менялось качество сжатия в коде, кэш сбрасывается через `SEED_FRESH_ASSETS=1`.

## Чего демо не показывает

Дыры материала и сида — что сцена не разыгрывает, где материал придуман, что оставляет прогон продаж — собраны в `DEMO.md`. Ограничения самой платформы живут в `DEFERRED.md` её репозитория.
